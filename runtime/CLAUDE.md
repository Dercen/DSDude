## Layout
- `core/include`: public headers (`value.h` cells, `fixed.h`/`number.h`/`numfmt.h` numbers, `dsdb.h` loader, `vm.h`,
  `dsd_platform.h` C11, `dsd_log.h` C8 lines, `game.h` boot/frame, `errors.h` R5xx, `dsd_limits.h` C13 values).
  Header names never shadow libc ones (`dsd_strings.h`, `dsd_limits.h`, `dsd_random.h`).
- `core/src`: portable C11 compiled by both builds (`vm.arm.c` in ARM mode + ITCM on the DS); `builtins/` one file
  per area, wired in `builtins/table.c`; `vendor/` libnds trig at 7fd8ccb.
- `host/`: the host platform, key scripts and `dsdude-host`'s `main.c`. `tests/`: the C test runner.

## Test before each commit
```
make -f runtime/Makefile.host test
```
Builds `dsdude-host` and runs the tests at -O2 and with the UBSan trap. WS0 also runs it on Windows at integration.
Cloud session: see the Cloud setup block in docs/kickoff/ws2.md.

## Isolation
Hand-assembled .dsda fixtures from packages/dsdb, host build only; no emulator needed until CP-B. Every `dsdude-host` run passes `--seed N`.

## Rules
- Flags on both compilers: `-std=c11 -O2 -fwrapv -fno-strict-aliasing -funsigned-char`, no floats, fixed-width seam types.
- No `printf` family, `qsort`, `rand` or floats in `core/`; script-value divisions go through `fixed.c`; big buffers are static.
- Generated `.dsdb` fixtures only via `node tools/gen-dsdb.ts`, in the commit that changes the `.dsda`.
- `runtime/package.json`, `tsconfig.json`, `vitest.config.ts` and `src/**` are WS3's.
